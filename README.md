# Расписание МГТУ

Сайт с поиском группы, сохранёнными расписаниями и работой без интернета. Публикация: https://zaretsky123.github.io/mgtu-schedule/.

## Как устроены данные

Источник — общедоступные страницы https://local.mkgtu.ru/raspisnew/print.php. Документированный открытый API не используется: Python-обработчик читает HTML, проверяет выбранную группу, дни, время, чётность и подгруппы. Для заочных сессий сохраняются конкретные даты. Такие занятия не повторяются каждую неделю.

`university-data/catalogue.json` содержит каталог, состояние подключения и дату последней проверки каждой группы. `university-data/groups/<id>.json` содержит расписание выбранной группы. Пользователь загружает каталог и только нужные расписания, а не все пары университета.

Каталог источника включает 853 записи, в том числе старые группы, одинаковые названия и служебные записи. Это не число действующих групп. В поиске сначала показываются уже подключённые расписания. Для ещё не подключённых записей виден статус; если в источнике нет занятий или формат пока не поддерживается, доступна ссылка на сайт вуза.

Тип занятия и преподаватель сохраняются так, как их указал вуз. Если тип не указан, сайт не угадывает его. Иногда фамилия записана прямо в названии предмета вместо отдельного поля — она остаётся в исходном тексте. Группы со ссылками на внешние таблицы не выдаются за полностью подключённые: для таких источников потребуется отдельный обработчик.

Текущий учебный период — 1 сентября — 27 декабря 2026 года. Сессии с датами за его пределами не публикуются как текущее расписание. Недельные записи без дат следуют чётности источника; отсутствие дат в источнике не позволяет надёжно определить, является ли такая запись архивной.

## Постепенное подключение и автообновление

В Actions есть workflow **«Обновление расписания МГТУ»** (`.github/workflows/update-university.yml`). Он запускается ежедневно в 05:43 по Москве; GitHub может задерживать запланированные запуски. При изменении обработчика также выполняется проверочный запуск.

По умолчанию (`gradual`) каждый запуск:

1. Обновляет каталог подразделений и групп.
2. Проверяет все уже подключённые расписания.
3. Пробует подключить ещё до 40 записей, распределяя попытки между подразделениями.
4. Сохраняет успешные результаты, записывает статусы остальных и публикует сайт.

Сначала проверяются ещё не обработанные записи. Неудачные подключения повторяются не чаще раза в неделю. 40 — число попыток, а не обещание 40 готовых групп: в источнике бывают пустые, старые и неподдерживаемые расписания.

Пустая страница, неправильная группа, ошибка сети или неизвестная структура не заменяют последнюю успешную версию. Ошибка обновления ранее подключённой группы помечается на сайте и делает запуск workflow неуспешным; остальные группы продолжают обновляться. Ожидаемое отсутствие расписания у новой записи не останавливает расширение. Если весь каталог недоступен, текущие файлы сохраняются.

Из Actions → Run workflow можно выбрать:

- `gradual`: подключённые группы и следующая партия по 40;
- `connected`: только подключённые;
- `all`: попытка проверить все записи;
- ID через запятую: выбранные группы, например `3027,3028`.

Сводка запуска содержит число доступных расписаний по подразделениям. Успешные данные фиксируются коммитом; запрос Pages build публикует и изменения от автоматического коммита.

## Сохранённые расписания и автономная работа

Поиск не зависит от регистра, пробелов и дефисов: `ст 12`, `ст12`, `СТ-12` дают одинаковые результаты. Выбор группы сразу открывает и сохраняет её в «Мои расписания» без дубликатов. Последняя открытая группа восстанавливается при следующем входе. Из списка можно переключиться на другое расписание или удалить запись.

При повторном открытии сохранённые пары появляются сразу, затем сайт проверяет свежие данные в фоне. Ошибка загрузки не стирает сохранённое расписание. При восстановлении соединения проверка повторяется.

`sw.js` сохраняет оболочку сайта: HTML, стили и необходимые модули. Кроме того, в кэше остаются успешно открытые расписания и каталог. После первого успешного открытия сайт можно снова запустить без интернета. Статус готовности указан в настройках. На домашний экран можно добавить сайт через меню браузера; `manifest.webmanifest` задаёт название и иконки.

Для первого открытия сайта и новой, ещё не загруженной группы нужен интернет. Изменения расписания придут после восстановления сети. Автономное хранение ограничено конкретным браузером и устройством; очистка данных браузера удаляет заметки, сохранённые группы и кэш. Регистрации и синхронизации между устройствами нет.

Подгруппа запоминается отдельно для каждой группы. Общие занятия видны всегда. Все подгруппы доступны по умолчанию. Настройки отображения общие: компактный вид, пустые пары и индикатор заметок. Заметки сохраняются на устройстве отдельно по группе; удаление группы из списка не стирает заметки.

## Разработка и проверка

Зависимостей Python устанавливать не нужно — обработчик использует стандартную библиотеку. Для готового интерфейса установка npm и сборка не требуются.

```sh
python -m http.server 8000
python -m unittest discover -s scripts -p 'test_university.py'
node --test tests/offline.test.mjs
python scripts/update_university.py --batch-size 40
python scripts/update_university.py --ready-only
python scripts/update_university.py --cached-catalogue --groups 3027,3028
```

Для service worker нужен HTTPS или localhost. При изменении оболочки обновите версию кэша и список файлов в `sw.js`, а также параметры версий в HTML и импортах. Перед публикацией проверяйте, что все файлы списка существуют. Автономная оболочка обновляется целиком; старые сохранённые расписания остаются доступны.

## Публикация

Файлы находятся в корне ветки `main`. Settings → Pages: Deploy from a branch, `main`, `/ (root)`. Пустой `.nojekyll` отключает обработку Jekyll. Workflow требуется разрешение записи Contents и Pages; они заданы в его YAML.

Проект независим от старых расписаний 302 семинарской и СТ-11. Эти два репозитория и контроль СТ-11 при расширении общего сайта не меняются.

Расписания преподавателей и импорт внешних таблиц — последующие этапы. Каталог аудиторий не планируется.
